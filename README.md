# 事故处置情境演练编排台（Incident Drill Studio）

供培训师**编排事故处置情境**、学员在浏览器中**按当前现场状态逐步推演**的本地 Web 应用。

- **技术栈**：Node.js（Express）+ SQLite（better-sqlite3）+ 原生浏览器单页界面，无外部服务依赖。
- **布尔现场状态**：每个情境至多 8 个布尔状态，选项带「生效条件」与「状态变更」。
- **发布前自动检查**：从初态出发枚举所有可达的「节点 × 状态」组合，检查
  1. 可达的非结局局面不能无路可走（**死路**）；
  2. 不能存在可无限循环而永远到不了结局的路径（**无限循环**）。

  不满足时给出**可逐步复现的路径**并拒绝发布。
- **发布即冻结**：每次发布生成一个不可变版本快照；已开始的会话永远沿其开始时的版本继续，新会话自动使用最新版。
- **乐观并发控制**：每次选择必须携带当前步号 `step`；步号过期或条件不满足时返回 **409 + 原因 + 现状**，会话不推进。
- **草稿保存校验**：无效引用（指向不存在的节点/状态）、同一状态上 `true/false` 矛盾条件、重复 ID、空标题等一律拒绝保存。

首次启动会自动建库并内置一个已发布的示例情境《化工反应釜超压事故处置》，可直接演练或在此基础上修改。

## 一、启动方式

### 方式 A：Docker Compose（推荐，一键启动）

```bash
docker compose up -d --build
```

启动后访问：

> **http://localhost:3000**

停止：`docker compose down`（数据保留在命名卷 `drill-data` 中）；
连同数据一起清除：`docker compose down -v`。

### 方式 B：本地 Node 直接运行（需 Node.js ≥ 20）

```bash
npm install
npm start
```

访问地址同上： **http://localhost:3000**

> `better-sqlite3` 含原生模块，安装时需要可联网下载预编译包；若需源码编译，请确保机器上有 Python 3、make 与 C++ 工具链。

## 二、配置项（环境变量）

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | HTTP 监听端口 |
| `DB_PATH` | `./data/drill.db`（本地）/ `/app/data/drill.db`（容器） | SQLite 数据库文件路径，所在目录自动创建 |

Docker Compose 下修改宿主机映射端口，编辑 `docker-compose.yml` 的 `ports`，例如改为 `8080:3000` 后访问 http://localhost:8080 。

数据库使用 WAL 模式；Compose 方案通过命名卷持久化 `/app/data`，重建容器不丢数据。

## 三、使用说明

界面顶部两个标签页：

### 1. 培训师编排
1. 左侧「情境库」选择或新建情境；
2. 定义至多 8 个**布尔状态**（ID、显示名、初始值）；
3. 编排**节点**（情境描述文本、是否结局）与**选项**：
   - 生效条件 `requires`：仅当当前状态全部满足时该选项对学员可见可选；
   - 状态变更 `sets`：选择后把指定状态置为 true/false；
   - 跳转目标 `next`：选项指向的下一个节点；
4. 指定**起点节点**，至少定义一个**结局节点**；
5. 「🔍 发布前检查」可随时预览检查结果（含可复现路径）；
6. 「💾 保存草稿」：结构不合法（无效引用、矛盾条件等）会被拒绝并逐条列出；
7. 「📌 保存并发布新版本」：通过结构校验 + 可达性检查后冻结为新版本（v1、v2……）。

### 2. 学员演练
- 选择已发布情境开始（自动取最新版本），或凭会话码/恢复链接继续旧会话；
- 页面展示：当前情境节点与描述、**当前现场状态**、**可选项**（条件不满足的选项以锁定形式展示原因）、以及**走过的完整路径**（每步含选择与事后状态）；
- 每次选择随请求提交当前步号；若页面过期（例如多标签页同时操作）或选项条件已不满足，服务器返回原因与最新现状，本次操作不推进。

## 四、HTTP API 摘要

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/scenarios` | 情境列表（含最新版本号） |
| POST | `/api/scenarios` | 创建情境（草稿即做结构校验，不合法拒绝） |
| GET | `/api/scenarios/:id` | 草稿 + 已发布版本列表 |
| PUT | `/api/scenarios/:id/draft` | 保存草稿（无效引用/矛盾条件返回 400 及明细） |
| POST | `/api/scenarios/:id/validate` | 仅检查不落库（结构 + 可达性，返回可复现路径） |
| POST | `/api/scenarios/:id/publish` | 发布冻结新版本；不通过返回 422 及复现路径 |
| GET | `/api/scenarios/:id/versions/:vid` | 查看某冻结版本内容 |
| POST | `/api/sessions` | 开始会话（默认最新版，可指定 `versionId`） |
| GET | `/api/sessions/:sid` | 查询会话现状（选项/状态/路径） |
| POST | `/api/sessions/:sid/choose` | 提交选择，body：`{ "optionId": "...", "step": 0 }`；步号过期/条件不满足返回 **409** 与 `current` 现状 |

选择被拒绝时响应示例：

```json
{
  "error": "choice_rejected",
  "reason": "stale_step",
  "message": "步号过期：你提交的是第 0 步，当前应为第 2 步……",
  "current": { "step": 2, "node": {...}, "states": [...], "availableOptions": [...], "path": [...] }
}
```

## 五、检查算法说明

把「当前节点 + 8 个布尔状态的取值」编码为一个配置（位掩码，全空间最多 `节点数 × 256` 个）。从 `(起点, 初态)` 做 BFS：

- **死路**：可达且非结局、却没有任何满足条件的选项的配置；报告 BFS 路径。
- **无限循环**：以「存在通向结局的路径」为良态做不动点标记，剩余坏配置子图中的环，即一条可永远重复而不经过任何结局的路径；报告「到达循环入口的路径 + 循环体」。

此外还会输出不阻断发布的警告：不可达节点、在任何可达状态下都永远不可选的选项等。
